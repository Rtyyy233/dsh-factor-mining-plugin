## 交付内容

### 1. R6 里程碑边沿触发（消费制）
- 旧：`accepted_n % 3 == 0` 电平触发——入册数停在倍数上永远推荐同一 query，审计答没答引擎看不见（空转实录的引擎侧根源）。
- 新：入册数**跨入**倍数时发一次，`drive_bk.milestone` 记账消费；下一个里程碑（42/45…）才再发。答卷不检测：正交性硬保证在入册时的机器正交门上，query 只是叙事层提醒。崩溃最坏丢一条里程碑、不重发（先记账后返回）。

### 2. R6.5 drain 指令（机械库存清空 → 供数型换向）
- 判据（库存型，非行为型）：无 pending、无 pending_rejected、无灵感重置声明、深化队列空（含"trail 空"但**排除"不可算"**——计算失败不冒充排干）、已验证未入册 <3（否则 compose 优先）。
- 指令文本：随机因子优先（本地通道永远可用）、论文次之；供数型探索语义（幸存者是选择不是结论）。
- 生命周期（`_govern_decide`）：间隔窗（默认 15min）内原键续供——注入器同键去重静默；过窗计数 +1 换新键续发；超 `drain_max_emissions`（默认 3）→ **drained 收摊**。

### 3. 零增长总闸（`_govern_decide`，空转/停摆双治）
- 增长定义：本线回合数或全局试验数相对上次快照前进（调用方 `drive_bk` 落账重置计数——**收摊态可被任何新落账自动解除**，非 finalize/test 锁）。
- 非 drain 策略的卡住判定：零增长超 `stuck_after_s`（默认 30min）且无在途异步评估（`_async_jobs` 守卫，长评估防误伤）→ nudge 补推（非可重推类型，键带序号；间隔窗内维持同键静默）；超 `nudge_max`（默认 3）→ **stalled 收摊**。
- 覆盖两个方向：continue 可重推空转（补推接管后不再返回 continue）与同键去重停摆（nudge 换新键重新点燃）。
- 误报无害化：nudge 文本明示"评估进行中回报进度即可、无需中断"。
- 实现细节：增长不短路 drain 首发（否则首查快照初始化被判增长 → 首发被跳过、第二查才记账 → 首两发键不一致一分钟内重复推送——集成测试抓出后修正）。

### 4. 收摊态（drained / stalled）
- `state=may_stop` + 对应 stop_kind + reason（明示"任何新落账自动解除，死线收官注入不受影响"）；注入器现有 may_stop 分支自然静默，**TS 层零改动**。
- 不复用 finalize（test 锁语义不污染）、不用持久 stop 标志（查询时重推导）。

### 5. 遥测
- loop 响应新增 `governor` 块：drained / since_growth_s / drain_emitted / nudge_emitted / milestone_consumed / last_action / 阈值——engine_orders/runner 侧自然透出。

## 状态阶梯（终态）

```
正常挖矿 continue（状态变化驱动换键；磨矿=每轮有实质工作，非空转）
  → 入册跨里程碑：query 发一次即消费（不检测答卷）
  → 机械库存清空：drain（随机优先论文次之；15min 间隔、3 发上限）
  → 零增长卡住（任何策略）：nudge 补推（30min 判窗、异步在途不判、3 发上限）
  → 上限耗尽零增长：drained/stalled 收摊（may_stop 静默；新落账自动解除）
  → 死线到点：收官注入（注入器现有机制，检查次序在引擎查询之前，不受收摊影响）
```

## 已知残余（声明）
- 死线下 stuck_after 窗内的 continue 仍会被重推（可重推类型无上限）——上限 = stuck_after（30min）后 nudge 接管，之后有界收摊。要归零须改注入器（用户决策：不动）。
- 磨矿经济：随机通道在静态数据上的命中率趋零时，drain 循环产出的是低价值试验（墙随试验数对数缓升，死线封顶）。算子扩容（42→59）后随机通道命中率待实测。

## 生产复犯与二次修复（2026-09-19 下午，用户报告"实际上还是空转"）

**现场**：总闸已部署（两线 drive_bk 在、里程碑 39/30 已消费），但 `drain:0 / nudge:0` 从未触发；个股线 engine 轨迹 02:01 后冻结，会话却持续分钟级一轮。

**根因（三层叠加）**：
1. **增长定义把叙事回合算成了增长**：旧定义 `(agent_rounds, n_trials) 前进`。等待环的每句"审计闭账维持"都被写成一条 next_hypothesis 轨迹（叙事回合每轮 +1）→ 总闸的计数被它永远重置 → 卡住判窗永远走不完、drain 永远不触发。生产 drive_bk 的 drain=0/nudge=0 正是这个死相。
2. **nudge/drain 键编了回合数**：回合每轮变 → 键每轮变 → 注入器同键去重永远咬不住。
3. **换措辞的自续 pending**：模型每轮换个说法重申"等待环 v3"，逐字相等的冻结检测（R5）永不触发——但此层不需要单独修，nudge 阶梯天然兜住。

**修复**：
- 增长 = **本线引擎试验数（n_trials_lane）前进**——真评估落账才算，说话不算；他线/他会话的试验也不重置本会话判窗。
- nudge/drain 键只编 lane_trials（零增长期间稳定）+ 序号，去重可咬合。
- 新增生产复犯回归测试 `test_waiting_loop_narrative_does_not_disarm_governor`（叙事轨迹连写 + 判窗走完 → nudge 接管 → 间隔窗内同键静默，绝不回到可重推 continue）。

修正后的空转轮廓：卡住判窗（30min）内 continue 仍会被重推（可重推类型、死线无上限——已知残余，上限即判窗长度）；判窗一过 nudge 接管，间隔窗内注入器静默；三发后 stalled 收摊直到死线/新落账。

## 终稿（2026-09-19 晚，用户拍板：超时换向制，无终态）

**用户质询**：收摊态（drained/stalled）会让预定任务在死线前静默——违反"死线=最低期限非收摊点"纪律；且收摊判据（三发无响应）远弱于真终态的枯竭证据，等于给复杂推送偷偷加了个弱判据终止阀（2026-08-24 用户决定：复杂类型不设上限，由引擎机械停点约束）。

**用户方案（终稿）**：一段时间没有试验落账 → 引擎直接注入 rotate 重置灵感。无上限、无终态；死线收官与 finalize 是仅有的结束方式。比复述式心跳更优的原因：换向直接作废自我续命的等待环声明（补推指令里"执行上一条声明的假设"对等待环等于请它继续等）。

**实现变更**：
- `_govern_decide` 动作集缩减为 {pass, drain_hold, drain_emit, rotate_hold, rotate_emit}——drained/stalled/nudge 全部退役。
- drain（库存清空供数指令）保留：15min 间隔、3 发预算；预算耗尽未到超时窗 → 原键续供静默，到窗 → 落入超时换向。
- `_timeout_rotate_strategy`：type 复用 rotate（注入器非可重推→同键去重静默）；键 = `rotate-timeout:{序号}:{本线试验数}`——序号保证每次超时换新键恰好一注，试验数零增长期稳定使去重咬得住；指令文本留"在途申报"口子（评估/构造进行中回报进度并继续，不必换向——防误伤长评估；异步作业守卫同样保留）。
- 顺带修一个隐性坑：`bk.get("growth_ts") or now` 把 0.0 当缺失（Python 假值陷阱）——显式判型取值。
- 配置：`nudge_max`/`nudge_spacing_s` 删除；`stuck_after_s` 语义 = 超时换向窗口兼重发间隔（每窗最多一注）。

**终态轮廓**：
```
正常挖矿（状态变化驱动）
  → 里程碑 query 一次即消费
  → 库存清空 → drain（15min×3）
  → 无落账超 30min（异步在途不判）→ 超时换向 rotate（每 30min 一注，无上限）
  → 任何新落账 → 全部复位
  → 死线收官 / finalize → 结束（仅有的两种结束方式）
```
死线内最坏节奏 = 每 30 分钟一条 rotate；预定任务永不静默。
