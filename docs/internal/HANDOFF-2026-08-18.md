## 1. 项目是什么

DSH（DeepSeek Harness）平台的因子挖掘插件：让一个 LLM Agent 在**引擎强制的研究纪律**
下自主挖掘截面因子。核心哲学一句话：

> **Agent 的自由在「挖什么」，不在「怎么验证正确性」。**
> 一切依赖 Agent 自觉的纪律都会失效；一切引擎强制的纪律都必须可被验证。

三层结构：Python 引擎（评估/纪律/校验）← TS 服务层（JSON-RPC over 子进程）←
TS 工具层（暴露给 LLM 的 factor_* 工具）+ SKILL.md（行为纪律）。

## 4. 数学口径基准（复现审计的锚点）

**已验证的复现锚点**（2026-08-18 独立复现过，10 位小数零偏差——你可用它校准你的复现环境）：

- 数据：`life-os/tmp/etf_liquid_cache.parquet`（long 格式：symbol/eob/open/high/low/close/volume/amount；T=2822, N=652, 2015-01-05~2026-08-13）
- 因子（曾入册）：`ts_sum(cs_scale(cs_rank(negx(amount))), 5) / 保号除法(ts_std(amount, 20))`
- 口径：horizon=20 t1 执行（fwd=close[t+20]/open[t+1]-1）、sample_step=20、min_periods=max(2,w//2)（**ts_std[20] 是 10 不是 2**——复现偏差的头号来源）、pit=amount>0、MIN_POOL=30、dev_end=2021-12-16（auto）
- **期望值：ic_mean_train=0.0576261596、ic_ir_train=0.4113881816、n=84、2015..2021 年度 IC 七年逐位一致、skew=-0.030808、kurt=2.347871、walk_forward fold1(2021-12-27~2022-10-27) ic_mean=+0.032228**

关键公式（`evaluate.py`，均有单测）：
- DSR（`_deflated_sharpe_p`）：sr0 = pool_std·[(1-γ)·Φ⁻¹(1-1/N) + γ·Φ⁻¹(1-1/(N·e))]，γ=0.5772；N=1 → sr0=0；**N>1 且无 pool_std → 拒绝给 p**（不给不可信数字）；p = 单尾 erfc。历史修正记录：√(lnN)→√(2lnN)→B-LP 池缩放（前两版尺度全错：N>1 全灭/N=1 零惩罚）。
- block bootstrap z = mu/se（旧版 (mu-boot_mean)/se 恒≈0，已修）。
- audit 的 spearman = Pearson-of-ranks（与 IC 同构，tie 一致性修正）。

## 5. 开发史教训（为什么你要怀疑「设计在工作」）

五处「设计存在但从首日起失效」的实锤，全部 2026-08-18 一天内发现：

- **E1 多重检验五环断裂**：① n_trials 计数接在 mining_state.round 上，而 agent 的工具走 append_trail 从不触发 record_round → 恒 1；② DSR 公式缺池缩放，N>1 时 p 恒 1.0（荒谬输出掩盖了①）；③ SKILL 指定的 evaluate_batch 工具入口无条件编译单个 source → **从部署首日起从未成功执行过一次**（agent 三次重试三败被误诊为「传参错」，实测取证发现参数完全合规）；④ seed 重放：explore 与 null 校准同默认 seed，整轮「探索」是 null 前缀重放；⑤ 即使①-④全修好，deflated p 也只是报告数字——两道入册判据的代码里根本没有它（注入铁证：z=7.08/p=0.9997 → verdict=pass + accepted=True）。
- **E2 walk_forward test 泄漏**：test_lock 只护 evaluate_test 一个入口。
- **E3 同名入册**：hash 铁律防了换名、没防同名。
- **E4 契约链断裂**：每个工具的参数描述单独正确，但生成器输出不满足下游契约——描述治不了跨工具断层。
- **E5 确认不落盘**：用户在 ask 里确认的三区没回写 config，重启即失。

**审计方法论建议**（从上述教训归纳）：对本文 §3 每一条设计，不要满足于「代码里存在」——
按「计算→判据→拦截」三层验证它真的在链路末端起作用；对每个工具做一次**本地直调复现**
（agent 失败时先怀疑工具本身）；对每道门做一次**注入/绕过尝试**。

## 6. 已知未闭合/遗留问题（诚实清单——审计者不必浪费时间重新发现，可直接验证或深挖）

1. **receipt 降级不拦截**（最重要的已知洞）：编造/篡改 diagnosis（含伪造 deflated p=0.001）→ receipt 对不上仅 verified=False，**accepted 判定仍用提交方带来的数字** → 理论上可绕过 D7/D8 门控。实测 agent 一直传真实 evaluate 结果，故未发生；但这是设计缺口。攻击面：`registry.submit` 直调 + 手构 diagnosis。
