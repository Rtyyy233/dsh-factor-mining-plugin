# 挖掘不停止纪律 —— 停走权归属、四把锁与永续不变量

**它是什么**：一条宪法级纪律——**挖掘阶段的停走只认死线与用户指令，
引擎与模型都无权制造终态**；在死线期内，会话不允许以任何形式静默。
它的完整形态是四把锁（模型禁自停、边沿触发消费制、死线旁路堵漏、
回合节奏治理）、一部三轮演进史（有界补推总闸 → 生产复犯修正 →
终稿超时换向制）与一条 2026-10-03 定稿的**永续不变量**（除死线与
用户指令外无任何终态）。本篇讲纪律与历史；判窗、双轴、键编制等
现行机制细节在 [rotate-and-growth.md](rotate-and-growth.md)，三原语
判定层在 [three-primitives.md](three-primitives.md)。

**它的位置**：贯穿引擎停走判定、策略选择、注入投放三层——纪律是
原则层，四把锁是它的机械落点，三轮演进是它被生产事故反复锤出来的
过程。

**上下游**：

| 方向 | 模块 | 关系 |
|---|---|---|
| 上游 | 用户 | 死线来源、数据轮换、真终态后的接管者 |
| 上游 | 引擎续行判定（三原语） | "下一轮干什么"的唯一合法来源（continue/expand/rescue；停点已废止） |
| 下游 | 策略选择器 | 纪律决定"永不静默"的策略供给 |
| 下游 | drive 注入器 | 纪律的投放层（兜底扫描默认常开） |
| 相邻 | [deadline-mechanism.md](deadline-mechanism.md) | 死线＝最低期限的语义承载 |
| 相邻 | [delivery-three-channels.md](delivery-three-channels.md) | 纪律如何送达模型 |

## 一、纪律本体：停走权的三层归属

- **模型层（禁自停）**：模型对"停不停"零权——没有引擎背书的合法停笔
  形态（历史上曾由方向段轮次／簇试验上限／IC 改善收敛／finalize 落锤
  触发停点，2026-10-03 起全部废止，见引擎层）。停下来等用户指示、写
  "本次探索结束"然后停笔，都是违规。**穷尽宣告不当结论收**："因子
  空间已穷尽／天花板／理论上限／建议换池子"写进下一步假设会被引擎
  拒收（`pending_rejected` 拒收门保留），同款文本即使已存在于旧轨迹，
  回显时也降级为"已拒收"并要求重写——实测十二次穷尽宣告全部为假，
  每次宣告后同一池子都挖出了新因子族。2026-10-03 起这面拒收门与
  穷尽谓词互为两面：引擎不再只说"不收"，还在状态页用反例回答
  （前沿还有哪些节点、井口水情、三通道救援成熟项——见
  [three-primitives.md](three-primitives.md)）。"想法队列空了"不等于
  "空间挖尽了"，后者只有穷尽谓词有资格宣判，且宣判结果是告警而非
  停机。
- **引擎层（永续，无停点）**：2026-10-03 定稿后引擎侧**不再有任何
  终态**——loop.state 值域钉死 {running, must_rotate}（may_stop 退役）；
  finalize（终局落锤）与连败 streak 停点删除（`check_termination`
  任何输入下不再返回它们，性质测试枚举边界值锁死）；全局收敛只做换向
  触发；test 一次性锁保留为工具级硬锁，烧毁后走状态页告警（"test 已
  烧，建议数据集轮换"）不停推进。停走只有两个外部来源：死线到点收官、
  用户指令。
- **用户层（主权事项）**：数据集／池／频率／数据源轮换是用户操作，
  不是模型能执行的动作，也不是停笔理由——认为该换数据时随里程碑
  汇报上报（一句话即可），然后继续在当前数据上挖掘。死线时刻同样
  只认用户口述。

## 二、四把锁：每把锁后面一起事故

### 锁一：边沿触发＋消费制（防"电平触发无消费"的重注机）

- **防什么**：条件持续为真就持续推荐同一指令——入册数停在 3 的倍数上，
  里程碑审计指令永远重推；合成库存常驻时合成指令每回合都挂出，且键
  里编了回合数（每回合都是新键），注入器同键去重永不咬合——个股线
  一夜 13 连注实录。
- **修法**：边沿触发一次即消费——跨入条件时发一次、记账消费；条件
  再满足（下一个里程碑、库存量变化）才再发。审计答没答引擎看不见
  （答卷不检测，硬保证在入册时的机器门上），但同一事件绝不重复催。

### 锁二：死线旁路堵漏（防"武装了死线反而空转"）

- **防什么**：死线武装让连续简单上限让位后，"上限保险丝＋电平触发"
  叠加成新漏洞——一夜 03:00-10:00：死线在身、里程碑指令电平重推、
  简单上限已让位，一个排干了库存的会话分钟级空转约 450 回合直到
  死线到点。
- **修法**：死线只接管"停止条件"，不接管"该干什么"——方向供给照常
  走策略选择器；锁一（消费制）与锁四（回合节奏）补齐后，空转的三
  个成分（无消费、无节奏、无上限）各被一把锁管住。
- **2026-10-03 演进**：「连续简单注入 ≤5 次让位真人」分支整体删除
  （**连注不限**）——它专咬无死线的日间挖掘（活体实证：上限一到，
  日间会话就躺平等真人）；防复读护栏移交引擎侧（同一欠账推 3 次
  未消账 → 升级告警用户＋**继续推**，见
  [three-primitives.md](three-primitives.md)），上限保险丝就此退役。

### 锁三：模型禁自停（防"体面停笔"）

- **防什么**：两种合法外形的偷停——"池满即停"（一次事故：导入的
  账本自带 8 只入册因子，"候选池满"条件从第一刻为真，会话 33 个回合
  全部停笔等推动，用户手动推了 31 次）与"写完总结就停"（同一事故的
  另一面）。此后"候选池满、已有入册因子"明确不是停点。
- **修法**：停走指令区随五个关键工具响应必带（state=running 必须继续
  内循环）；中途问询被禁止（决策留痕不留问）；里程碑简要汇报、不问。

### 锁四：回合节奏（防"会话还活着但什么都没发生"）

- **防什么**：分钟级一轮的空转与叙事喂钟——会话每轮写一条轨迹就算
  "有动静"，治理判窗永远走不完。
- **修法**：增长双轴＋超时换向——叙事碰不到的两个机械轴（本线试验
  落账、未命中缓存的评估派发）任一前进才算增长；零增长超窗即换向
  重推（判定细节见 [rotate-and-growth.md](rotate-and-growth.md)）。
  纪律从"审措辞"改为"审活动"：词表追不完模型造的新词，活动轴模型
  伪造不了。

## 三、三轮演进：总闸 → 复犯修正 → 终版换向

- **第一轮（有界补推总闸，2026-09-19 晨）**：针对空转实录设计——
  里程碑消费制＋库存清空的供数指令（drain）＋零增长总闸（卡住补推
  nudge，30 分钟判窗、三发上限，之后收摊）。设计自检发现两条残余
  （库存非空×模型失活、同键冻结停摆）由同一总闸兜住。
- **第二轮（生产复犯修正，同日下午）**：部署当晚用户报告"实际上还是
  空转"——三层叠加根因：增长定义把叙事回合算成增长（等待环每句
  复述都写轨迹，判窗被永远重置）；补推与供数的键编了回合数（每轮
  变键，注入器去重咬不住）；换措辞的自续待办（逐字相等的冻结检测
  永不触发）。修正：增长只认本线试验数（说话不算）；键只编线试验数
  ＋序号；补推阶梯天然兜住换措辞自续。
- **第三轮（终稿超时换向制，同日晚，用户拍板）**：质询收摊态——
  见第四节；方案改为"一段时间没有试验落账 → 直接注入换向指令重置
  灵感"，无上限、无终态；补推与收摊全部退役。终态阶梯：

```
正常挖矿（状态变化驱动）
  → 入册跨里程碑：审计指令一次即消费
  → 机械库存清空：供数指令（10 分钟间隔 × 3 发）
  → 无落账超 10 分钟（评估在途不判）：超时换向（每窗一注，无上限）
  → 任何新落账：全部复位
  → 死线收官 / 用户指令：结束（2026-10-03 起仅有的两种结束方式）
```

## 四、收摊终态否决：为什么"停"不能是弱判据

- **被否决的方案**：补推三发无响应 → 收摊（stalled）；供数三发耗尽
  → 收摊（drained）；收摊态允许会话静默等死线。
- **否决理由两条**：其一，**预定任务死线前静默本身违纪律**——死线
  是最低工作期限，收摊态让"挖到早上八点"的会话凌晨三点就躺平；
  其二，**收摊判据（三发无响应）远弱于真终态的枯竭证据**（全局收敛
  要滑窗对滑窗的数字、finalize 要测试区落锤）——等于给复杂推送偷偷
  加了个弱判据终止阀，破坏"复杂类型不设上限，由引擎机械停点约束"的
  既有决定。
- **终裁**：无上限换向取代收摊。换向优于复述式补推的原因：补推指令
  里"执行上一条声明的假设"对等待环等于请它继续等；换向直接作废
  自我续命的等待环声明。

## 五、永续不变量（2026-10-03 终稿）：停走权归用户

第三轮终稿仍留了三个引擎停点（finalize／连败／全局收敛静默），2026-10-03
总任务书（引擎 loop 三原语重设计）把它们全部废止，纪律升格为不变量：

- **除死线与用户指令外，无任何终态机会**。回退链结构性保证挖不完：
  expand 前沿空 → 井口水情句 → 三源轮转（文献→随机→机制）→ 随机
  生成兜底——"没方向"在结构上不可能成立。
- **loop.state 值域钉死 {running, must_rotate}**：may_stop 退役——引擎
  不再发"允许收尾"这个状态，模型没有任何"合法停笔"的引擎背书。
- **finalize／fail_streak 停点删除**：`check_termination` 任何输入下
  永不返回它们（性质测试 `test_perpetual.py` 枚举边界值锁死）；
  `_pick_strategy` 永不返回 None——注入器永远有指令可推。
- **test 一次性锁降格为工具级硬锁**：烧毁不再停推进，走状态页告警
  （"test 已烧，建议数据集轮换"）——锁守的是评估的诚实性（测试区
  只能消费一次），不是停走权。
- **穷尽宣告从"拒收"升格为"引擎用反例回答的查询"**：模型说"空间
  挖尽了"，引擎不收这个结论，而是在状态页回答——前沿还有哪些节点、
  井口水情如何、三通道救援有没有成熟项；穷尽谓词（C 空∧E 空∧R 空∧
  井干）成立时告警用户"建议数据集轮换"，不停机不静默。
- **停走权最终归属**：死线（用户口述时刻的机械执行）与用户指令——
  两者都是用户的；引擎与模型各自零权，这是"提议权归模型、续行权
  归引擎、停走权归用户"的三权分置终态。

## 六、退役清单（全史在案）

- **nudge（卡住补推）**：初版总闸的核心件，终稿删除——配置键清除，
  动作集缩减为五种（放行／供数保持／供数发射／换向保持／换向发射）。
- **drained／stalled（收摊终态）**：终稿删除（第四节）。供数指令保留
  但不再是终态——3 发预算耗尽后落入超时换向循环。**2026-10-03 注**：
  drain 语义随后再次翻转——近失/standby 非空从 drain 的否定条件变成
  rescue 通道的候选源（见 [three-primitives.md](three-primitives.md)）。
- **convergence（全局收敛停点）**：退役为换向信号——全局或族内枯竭
  都只做换向触发，不再当停点。
- **finalize（终局落锤停点）**：2026-10-03 删除——测试区一次性消费的
  语义保留在 test 工具级硬锁上，停点语义废止（永续不变量）。
- **fail_streak（连败停点）**：2026-10-03 删除——连败计数保留为信息
  字段，不参与停点；`max_fail_streak` 配置语义废止（stock 根历史
  global_fail_streak=1 为 migration 遗迹，不构成先例）。
- **may_stop（loop.state 值）**：2026-10-03 退役——值域钉死
  {running, must_rotate}；TS 侧对其它值的检查降级为纯保险丝。
- **注入器「连续简单注入 ≤5 次让位真人」分支**：2026-10-03 删除
  （锁二 2026-10-03 演进）；consecutiveSimple 计数保留仅供日志诊断。
- **"等待中"收件箱拦截**：随楔死恢复一并退役（见
  [drive-injector.md](drive-injector.md) 第五节）。
- 退役不删史：每个退役件的出生事故、服役期、退役理由都在案——机制
  与它的教训同寿。

## 成功样例：一次无人工推动的完整夜场（2026-09-30）

修复后桌面宿主的首个挖掘会话：首调门→选边→静默窗注入→技能纪律加载→
登记预期→评估→提交门→两只候选入册，全程 65 分钟零人工推动。期间引擎
的节奏治理在后台工作（试验计数逐笔入账、活动轴随评估派发前进、指令
区随状态换策略），用户只在场外看。四把锁在这场里全部处于"用不上"
状态——这正是设计目标：锁是给异常准备的，正常路径上纪律表现为会话
自己转下去。

## 失败样例：空转三修（2026-09-19，三轮演进的事故起点）

凌晨 03:00-10:00：死线武装的会话以分钟级节奏空转约 450 回合——每轮
都有动作（响应里程碑指令、复述状态），但没有一次真实挖掘。三轮修复
对应三层根因：引擎侧电平触发无消费（第一轮修）、增长定义被叙事喂饱
＋键编回合数（第二轮修，当天下午生产复犯抓回）、收摊态违反死线语义
（第三轮修，当晚用户质询拍板终稿）。一天三修不是折腾，是这条纪律的
成形过程：每一版都被生产实测打脸，每一次打脸都留下一个可回归测试的
修正。终稿此后再未出现整夜空转。
