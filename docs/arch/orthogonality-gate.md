# 正交门 —— 与既有池的相关性检查（0.80 软门语义）

**它是什么**：入册时刻的一道"账本是否已知"检查。显著性门与多重检验墙
回答的是"它自己是不是真的、运气排不排得掉"；正交门回答另一个问题——
"账本里是不是已经有一个跟它几乎一样的因子"。一个与在册因子逐日排序
高度重合的新因子，不带来新信息，只稀释账本的有效维度。

**它的位置**：入册事务内、各显著性门之后——只对将通过验收的候选执行
（未过验收者不入册，无冗余可言）；检查结果写进入册条目并存进在册基线。

**上下游**：

| 方向 | 模块 | 关系 |
|---|---|---|
| 上游 | 入册验收链 | 显著性／噪声／平度等门先过，本门最后对账本对表 |
| 上游 | 在册因子账本 | 检查的对象（秩缓存＝账本的数值基线） |
| 下游 | 在册基线（秩缓存） | 入册成功即追加本因子的秩，成为后续候选的对表对象 |
| 相邻 | 探索期双池对表 | 评估期提醒（第五节），与本门构成入册前后的两道相关检查 |
| 下游 | 测试区 | 软门语义下，测试区是冗余争议的最终仲裁 |
| 相邻 | 多重检验墙 | 墙对试验次数定价，本门对账本维度定价，互补 |

---

## 一、动机：门上线前的两笔审计旧账

一次全量正交审计发现两件事：量价相关域与历史已入册的一个系**同源**
——逐日平均相关约 0.70，且符号相反是构造性的（同一信息换了写法）；
尾部账本里同一结构的八连注册，两两相关最高到 1.000——同一个因子换了
八个名字。结论：显著性门只回答"是否真实"，不回答"是否已知"，必须补
一道对账本的门。

## 二、怎么查：秩缓存 + 逐日相关

- **防什么**：冗余入册稀释账本有效维度。
- **怎么查**：在册因子在开发区（训练截止之前）的逐日横截面秩，在入册或
  回填时一次性算好压成整数矩阵缓存。提交期检查：重跑候选因子 → 取其
  开发区逐日秩 → 与每个在册因子的缓存逐日算皮尔逊相关（**只计双方公共
  有效股数 ≥300 的日期**，截面太小相关不可信）→ 对日期取平均 → 平均
  相关绝对值最大的在册因子即为"最像的先例"。报告带前五名名单与数值。
- **成本边界**：对表是候选秩对缓存矩阵的逐日内积循环，提交期两秒内
  完成——贵的部分（在册因子全量重算）被摊到入册/回填时一次性付清。
- **报告什么**：最大相关与最像先例的名字、前五名名单（带正负号——
  符号相反的同源也是同源）、可比日期数、本次用的阈值；写进入册条目，
  此后随时可回看"它入册时跟谁像、像多少"。

## 三、阈值与动作：0.80 拒 / 0.60 标注 / 其余过

- **阈值**：平均绝对相关 ≥0.80 → 拒收动作；0.60-0.80 → 标注动作
  （条目记录冗余嫌疑，不拦）；<0.60 → 通过。
- **硬拒语义（可恢复的旧形态）**：拒收＝不入册、不烧名（重税墙的试验
  计数不动——被拒的是冗余不是无效），理由写明"与在册某因子同源，账本
  变更后可依程序重议"；出路是构造正交新方向，或确系同源变体时在信号
  说明里显式声明关系再走。

## 四、软门语义（现行默认）：标注 + 提示，不否决、不烧名

- **防什么**：防误伤"深挖式重组"——把一条已知强腿绑进新组合，恰是迈过
  重税墙、打开新域的唯一现实入口；而这类重组与在册强腿的相关天然偏高，
  硬拒与它结构性冲突。
- **怎么做**：配置默认软门——检查照跑，≥0.80 时动作从"拒收"降级为
  "标注"：入册照常，条目记冗余报告与提示（"冗余度超线——按用户决策
  降级为提示，提交照常入册；测试区为最终仲裁"）。设硬门开关可恢复旧
  硬拒行为。
- **边界**：0.60-0.80 的中档标注两形态共用；裁决权后移——真冗余最终由
  一次性的测试区消费判生死。

## 五、探索期对表：双池指纹检查（相邻但不同的另一道）

- **防什么**：等不到入册才发现重挖——探索阶段就该收到"疑似重复"的
  提醒。
- **怎么查**：有界双池各存因子指纹——活跃池（容量 64，评估通过/待审的
  强因子，按强度弱者滚动出池）与证伪池（容量 32，正式证伪的簇代表，最久
  未用滚动出池）。指纹＝不重叠采样日的因子值子矩阵（评估本来就算出因子
  矩阵，顺手采样，零额外执行）。新因子对表两步：拉平相关粗筛（绝对值
  ＞0.5 才进精算）→ 逐截面秩相关精算。
- **阈值**：数值相关 ≥0.90 报"疑似重复探索"；结构签名相似 ≥0.70 报
  "方法维度疑似重复（同一公式换数据/字段）"。
- **不过怎么办**：**提醒不是否决**——提示先查相似度检索、论证本质差异
  再继续；硬保证在入册时的正交门上（答卷不检测，门检测）。
- **边界**：证伪池成员不得再入活跃池（防重复挖坟）；全史只存文字不参与
  数值比对——审计职责不是去重负担；池有界保证对表成本与挖掘总量无关。

## 六、失败边界：基础设施失败不拒绝不烧名

检查链任何一环失败（在册源码缺失、日期错位、缓存损坏）→ 跳过并在条目
里记"跳过＋原因"，指引运行基线回填重建。设计取向：这道门是账本卫生
机制，不与显著性门（那边不可判定即拦截）比严——误拒一个真新域的代价
高于放行一个可标注的冗余。入册后的基线追加失败同样不阻断（可全量重建）。

## 七、里程碑正交审计：一次即消费

推进回路里另有一个独立的正交动作：某线入册满一定数量后，触发一次对该
线全部在册因子与账本的**正交性审计**——一次性消费（同一线不重复触发）。
它的定位是回看与教学（把账本冗余结构暴露给会话），不是门——正交性的
硬保证在入册时的机器门上，答卷本身不检测。

## 八、软门与近失队列的联动

正交门软化后，一批曾被冗余阴影压住的候选恢复了可挖性：历史上若干
"指标近失但与在册强腿相关偏高"的因子，在硬门时代既过不了正交门、又
够不着深化通道，两头堵死；软门把它们交还给近失队列与深化流程，由
测试区做最终仲裁。这是"检查用于知情、裁决后移到一次性区"的整体设计
取向在正交维度的落点。

## 九、基线的建造与重建（秩缓存生命周期）

- **怎么建**：全量重建＝对账本全部已入册条目逐只重跑源码、算开发区
  逐日秩、落缓存——同时给出失败清单（无源码/日期错位/重跑出错的名字）。
- **怎么维护**：入册成功即增量追加本因子（要求日期对齐且环境指纹一致，
  否则拒绝追加并提示重建）。
- **绑定**：缓存绑定环境指纹——换数据、改口径即整体作废重建；旧账本
  首次接入时先跑一次重建。
- **防什么**：缓存与账本脱钩（账本删了条目缓存还在比、或反之）——
  追加失败的条目宁可缺位也不硬塞，缺位由重建收敛。

## 成功样例：一次降级决策与它的复裁注记

正交门上线初期是硬拒形态。运行几天后暴露冲突：深挖战役的主力打法是把
在册强腿重组进更大的结构——这类候选过得了重税墙（强腿带着真实信号），
却常被 0.80 硬拒挡在门外。用户裁决降级为软门（标注＋提示，不否决、不
烧名），测试区为最终仲裁。归档注记同时记录了一次执行侧反复：软门改动
最初只落在主代码树，随后一次两树收敛时按用户复裁把软门行为移植归位
——决策本身与它的执行历史都在案。

## 失败样例：门缝——11 笔提交全部漏检

正交门的入口包装最初只落在主代码树；一台从工作树直驱的挖掘桥加载不到
它——导入失败后门**静默跳过**（不拒绝、不烧名，这是本门对基础设施失败
的既定姿态）。一晚直驱会话的 11 笔提交全部未经正交检查，10 条冗余因子
回流进账本；事后用反事实回放核对，多数笔本应被拒收。用户终裁：回流
条目**保留并补标注**，不翻案删账；教训入档——"两树并行时，单点修复
必须双向回流；"失败即放行"的门尤其怕部署不一致，因为它的失败方式恰好是
沉默"。此后正交门的入口与缓存装载被列为两树同步的强制对账项。
