# lane 隔离与首调门 —— 多会话共用一台引擎时的身份与选边

**它是什么**：一台宿主只跑一个 Python 引擎进程，全部会话的因子工具调用都
从它走。没有身份制度时，并行会话会互相接管对方的"下一步"——A 会话上一轮
声明的待办假设，会被当成 B 会话的义务去催办。lane 隔离把**意图按线分开、
计价留在全局**：每个会话一条线（lane＝会话身份），自己的待办假设、家族链、
方向段预算、灵感配额各管各的；而试验总数、多重检验墙、尾部门槛、证伪记忆
这些"事实与价格"全线的试验一起算——别的线多挖一发，本线的入册门槛照实
升高，这是多重检验的正确行为，不是串线。配套两件小制度：**会话↔账本
绑定**（一个会话同一时刻只属于一个账本，绑定落盘、重启不丢）与**首调门**
（没声明账本的会话第一次调用工具直接被拒，错线路径在机械上不存在）。

**它的位置**：横在会话工具面与引擎之间。上游是宿主里每个会话的工具调用
（工具层把会话身份盖进请求），下游是引擎的状态记账、判定与送达。

**上下游**：

| 方向 | 模块 | 关系 |
|---|---|---|
| 上游 | 会话工具面 | 每次调用携带会话身份（工具层盖入，模型伪造无效） |
| 上游 | factor_root_use | 会话选边的唯一合法入口（先绑定后放行） |
| 下游 | 推进治理与停走判定 | 判窗、义务、换向全部按本线读数 |
| 下游 | 多重检验墙／尾部门槛 | 计价全局——本线试验＋他线试验一起抬墙 |
| 下游 | drive 注入器 | 读同一份绑定表决定推哪条线的指令（跨通道同源） |
| 下游 | 推理日志（journal） | 日志线名独立解析，可与意图线不同（第五节） |
| 相邻 | 派生图与事件日志 | 事件带线名，试验计数按全局、活动按本线 |

---

## 一、lane 是什么、从哪来

- **防什么**：并行会话互相接管意图状态；单会话冒充多会话稀释计价。
- **怎么定**：解析链三条，先到先得——①请求参数里的 lane 字段（宿主工具层
  自动盖入会话 id，会话 id 清洗成只含字母数字连字符下划线、至多 48 字符的
  线名）；②环境变量（直连命令行／无宿主会话的并行进程用，开工时指定）；
  ③都缺 → 默认线。历史遗留的无标记条目一律归默认线（单线时代的唯一
  叙述者，数据不迁移、不回填）。
- **身份只来自基础设施**：模型在请求或条目里自己写的 lane 字段一律被覆盖，
  从不采信——身份是路由事实，不是叙事内容。
- **边界**：没有会话身份的上下文（工具回放、测试脚本）解析不到线名，回落
  默认线——单线用法下这是正确行为。

## 二、隔离边界：意图按线，计价全局

- **防什么**：两个坏方向一起防——意图串线（他线的待办催到本线头上）与
  计价漏数（本线的试验没算进全局墙）。
- **按线隔离的状态（说话算话的那层）**：待办假设义务、停笔宣言记录、
  家族链连击、方向段轮次与簇试验预算、同一句假设冻结检测、灵感重置
  声明与随机／机制发射配额、引擎可见活动计数、推进治理记账（上次策略
  键、增长快照、超时换向计数）。这些只统计本线条目，别的线的状态不会
  串进你的义务。
- **全局计价的状态（数字算数的那层）**：试验总数与有效数、多重检验墙、
  尾部门槛与近失清单、证伪记忆与方法重复嫌疑、入册账本、派生图。并行
  线知道彼此的证伪结果是收益不是污染；多重检验必须全量计数。
- **怎么核对**：并行时工具响应带一行线注记——"本线 N / 全局 M（其它线
  K）"：试验数与尾部门槛按全局计价，待办／族链／方向预算只统计本线。
  会话看到门槛升高又没挖过那么多，先看这行注记——是别的线的试验在
  抬墙，不是自己超时的那次调用完成了。
- **不过怎么办**：无需处理——这是记账事实，不是错误。

## 三、会话↔账本绑定：一户一账本，落盘重启不丢

- **防什么**：双账本部署（个股线与 ETF 线两套独立账本）下，新会话被隐式
  绑到默认账本——ETF 会话污染个股试验计数、收到错误账本的引擎指令。
- **怎么做**：一个会话同一时刻只属于一个账本；选边只能由会话自己调
  factor_root_use 显式声明（切换即重绑）。绑定写入用户主目录下的
  factor-session-bindings.json（会话→账本键值表）：先写临时文件再原子改名，
  中途崩溃不留半截；表有界（至多 500 条，超出的最旧条目让位）；读失败
  从空表起步（行为退回旧版），写失败仅内存生效。
- **重启免手动唤醒**：引擎重启后按落盘绑定恢复每个已知会话的路由，自动
  推进器的扫描名单也从这份文件的键集重建——静默会话照进扫描视野，不用
  人在重启后逐个唤醒。
- **边界**：无会话身份时绑定不落盘、仅当次生效。

## 四、首调门：未声明账本的第一次调用直接被拒

- **防什么**：隐式路由复活——绑定改落盘之前，新会话首调会被悄悄送进默认
  个股账本，错误绑定还会落盘扩散。
- **怎么查**：有会话身份、但绑定表里查不到记录的会话，第一次调用任何
  因子工具（factor_root_use 自身除外）时，门在工具层直接拒绝——本次调用
  零执行，根本不进 Python 引擎。拒绝文案给出二选一声明命令（个股线声明
  default、ETF 线声明 etf），模型照抄即可通过；声明一次，重启持久，本门
  永不再触发。
- **不过怎么办**：不存在"绕过"——门是代理层，任何方法调用都先撞门。
  唯一出路就是声明。
- **边界**：无会话身份的上下文（工具回放、测试）不走此门，回退单线用法。
  **跨通道同源**：注入器对未绑定会话同样静默不注入（宁可沉默也不把个股
  指令注进 ETF 对话）——两处判定读同一份绑定文件。
- **选边回执**：声明后返回两个账本的键与路径（教模型两线语义）＋所选
  账本的完整状态（含停走指令区，挖矿即刻受引擎驾驶）；未知账本键拒绝并
  附全表。

## 五、日志线名的独立解析（与意图线的分工）

- **防什么**：会话线名是随机长 id——按会话分线，每个会话一本推理日志，
  跨会话的信念继承断掉。
- **怎么做**：推理日志的线名单独解析——宿主配置的日志线名优先（一个账本
  一条日志线，跨会话共享信念），其次环境变量，最后才是会话线名。配置后
  各会话写同一条日志线；**意图层不受影响**——待办、族链、预算仍按会话
  线各管各的。日志线名同样只来自基础设施配置，模型自己写的字段不转发。
- **边界**：不配置时行为是"每会话一本日志"，合法但继承断链。

## 六、lane 参数双层契约：声明与转发缺一即静默丢参

- **防什么**：工具参数在工具面这一层被静默剥掉——参数没在工具清单里
  声明，宿主根本不会把它传进来；参数声明了但处理器没转发，请求到了
  引擎也是空的。两种缺口都不报错，只是参数无声消失。
- **怎么查**：每个携带线名的工具都要过两道——工具清单里声明该参数
  ＋ 处理器把它盖进请求。改参数时两侧同改、逐一勾稽。历史上这个缺口
  反复重犯（同族三犯）：第一次是轮询参数未声明，轮询请求被剥成"空源码
  的新评估提交"——一个注定失败的垃圾作业，三个同名运行中作业同时挂在
  队列里；第二、三次都是线号没转发——最近一次是 ETF 夜的随机生成调用，
  两线全部探索批的幸存者哈希都记到默认线，随机策略配额与活动记账跨线
  失真（当夜默认线活动计数比增长快照多出 33，恰约等于两线探索批总数）；
  全量对拍审计又抓出组合救援工具的同款缺口。
- **不过怎么办**：事后对拍是唯一的兜底——把工具面的参数清单与引擎侧
  实际消费的参数清单逐一比对。此后规矩入档：参数两侧同改；引擎侧对
  "空源码且无作业号"的请求直接拒绝并教正确用法。

## 成功样例：修复后首个会话的完整选边链

2026-09-30 桌面工具面修复后的第一个新会话：首调即触发首调门，拒绝文案
逐字返回；模型照抄声明 ETF 账本，回执带两个账本的键与路径和所选账本的
完整状态（含停走指令区）；随后进入 65 分钟完整自主挖掘，两只候选通过
全部门禁入册生产账本。全程线注记可读：本线试验 10 笔、全局试验数从
2994 走到 3004——意图隔离与全局计价在同一屏同时生效，账本归因无一笔
错线。

## 失败样例：ETF 会话重启后收到个股指令

绑定落盘制度出生前，绑定关系只存在引擎进程内存里。一晚宿主重启，内存
清空，ETF 会话的路由回落到默认账本——个股线的引擎指令被注进 ETF 对话，
错误绑定还会随使用继续落盘。这次事故定了两件事：绑定必须落盘（重启后
路由与扫描名单自动恢复）；未绑定会话宁可沉默也不注入（首调门与注入器
读同一份绑定文件）。同族的参数侧教训（第六节三犯）则确立了"声明＋转发
缺一即静默丢参"的双层契约铁律——静默丢参的可怕之处在于它不报错，只能
靠对拍审计抓。
